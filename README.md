# Лабораторная работа 4. Алгоритмический мини-пакет

В `algosi` выбран вариант 2 при нумерации с единицы. Номер получен по формулам `17 % 5` для лестницы и `17 % 3` для сортировок и очереди.

## Установка и тесты

Пакет проверен на Python 3.14.8. Команды запускаются из корня проекта.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m unittest discover -s tests -v
```

## Что делает пакет

- `algosi.stairs`. `count_ways_iterative(n)` и `count_ways_recursive(n)` считают способы подняться на `n` ступеней шагами по одной или две ступени. При `n = 0` засчитывается один способ без шагов. Отрицательное `n` вызывает `ValueError`, а аргумент неверного типа, в том числе `bool`, вызывает `TypeError`.
- `algosi.sorting`. `insertion_sort(vals)` и `fast_sort(vals)` принимают списки целых чисел. Обе функции возвращают новый список в порядке возрастания и сохраняют содержимое исходного списка.
- `algosi.queue`. `Queue` хранит элементы в порядке добавления. `add_value(value)` добавляет элемент в конец, `pop_value()` извлекает первый, а `peek()` возвращает его и оставляет в очереди. `len(queue)` даёт число элементов, `bool(queue)` показывает, есть ли в очереди элементы. На пустой очереди `peek()` и `pop_value()` вызывают `IndexError`.
- `algosi.generators`. `random_values`, `sorted_values`, `reverse_values`, `pochti_sorted_values` и `duplicate_values` возвращают списки заданной длины. Почти отсортированный список получается перестановкой нескольких соседних пар. Если передать случайному генератору тот же размер и тот же целочисленный `seed`, получится такой же список.

Для списка `[1, "2"]` обе сортировки вызывают `TypeError` при сравнении элементов. Кортеж вызывает `AttributeError` в `insertion_sort` при попытке сделать копию через `copy()`. В `fast_sort` та же ошибка возникает на пустом кортеже или кортеже с одним элементом.

## Сложность

| Операция | Время | Дополнительная память |
| --- | --- | --- |
| Лестница, цикл | `O(n)` | `O(1)` по числу хранимых значений |
| Лестница, рекурсия | `O(2^n)`, верхняя оценка | `O(n)` кадров стека |
| Сортировка вставками | `O(n)` на отсортированном входе, `O(n²)` в среднем и в худшем случае | `O(n)` на копию списка |
| Быстрая сортировка | `O(n log n)` в среднем, `O(n²)` в худшем случае | `O(n)` при сбалансированных разбиениях, `O(n²)` в худшем случае |
| Добавление, извлечение, просмотр, `len` и `bool` у очереди | `O(1)` | `O(1)` на операцию, сама очередь занимает `O(n)` |
| Генерация списка | `O(n)` | `O(n)` с учётом результата |

В оценках для лестницы сложение считается одной операцией. Рекурсивный вариант многократно пересчитывает одни и те же значения, поэтому для больших `n` подходит цикл.

Лимит глубины рекурсии показывает `sys.getrecursionlimit()`. В окружении проекта он равен 1000. При превышении лимита Python вызывает `RecursionError`.

Быстрая сортировка берёт опорное значение из середины списка. За один проход она раскладывает элементы по трём спискам для меньших, равных и больших значений. При сбалансированных разбиениях получается порядка `log n` уровней, на каждом обрабатывается до `n` элементов.

Если на каждом шаге в следующий вызов уходит группа всего на один элемент короче, глубина растёт до `O(n)`. Списки из предыдущих вызовов остаются в памяти до возврата из рекурсии.

## Бенчмарк

```bash
.venv/bin/python -m algosi.benchmark
```

Команда записывает результаты в `bench_res.csv` в текущей папке и перезаписывает его при повторном запуске. Полный контрольный запуск занял около четырёх минут.

Для каждого размера проверяются пять типов входа. Для случайных генераторов задан `seed=17`. Набор создаётся один раз, а перед каждым из пяти повторов берётся свежая копия. Генерация и подготовка копии идут до запуска таймера. Если сортировка меняет вход на месте, свежая копия позволяет начать следующий повтор в том же порядке. В CSV записана медиана времени в секундах. [Полный отчёт](bench_res.csv)

| Сортировка и вход | 100 000 | 1 000 000 | 10 000 000 |
| --- | ---: | ---: | ---: |
| Вставками, отсортированный | 0,0046 | 0,0503 | 0,4681 |
| Вставками, почти отсортированный | 0,0047 | 0,0471 | 0,4807 |
| Быстрая, случайный | 0,0890 | 1,2872 | 19,1749 |
| Быстрая, много дубликатов | 0,0095 | 0,0897 | 1,0463 |

На отсортированных и почти отсортированных списках время сортировки вставками растёт примерно пропорционально размеру. В отсортированном списке сдвигов нет, а в почти отсортированном их мало.

Замеры сортировки вставками на случайном списке, списке в обратном порядке и списке с большим числом повторов пропущены из-за ожидаемого квадратичного роста времени. В CSV у этих строк стоит `skipped`.

При каждом десятикратном увеличении случайного списка время быстрой сортировки вырастало примерно в 14 или 15 раз. Это согласуется с ожидаемым ростом порядка `n log n`.

В наборе с дубликатами всего десять возможных значений. Каждый шаг разбиения сразу выделяет все элементы, равные опорному. Поэтому глубина разбиения здесь ограничена числом разных значений, а время в замерах росло почти линейно.
